# План бэкенда (`apps/api`, NestJS)

У каждой задачи есть **результат** (что появится) и **критерии приёмки** (как проверить). Эндпоинты подробно описаны в [04-api.md](04-api.md), таблицы — в [03-database.md](03-database.md).

---

## BE-1. Каркас API и инфраструктура
**Результат:** запускаемый NestJS-проект в монорепо, подключённый к PostgreSQL.
- `apps/api` (NestJS 12, `@ig/api`), подключение `@ig/shared` и `@ig/config`; `@ig/shared` собирается через tsup в ESM+CJS для Node.
- Отдельный кластер PostgreSQL 17 проекта без Docker: `pnpm --filter @ig/api db:local init|start|stop|status` (порт 5434, данные в `%LOCALAPPDATA%/InstagramClone`). `docker-compose.yml` с PostgreSQL, Redis, MinIO и Mailpit — для тех, у кого есть Docker.
- Конфиг из env с валидацией Zod (`config/`), `.env.example`, порт API 3003.
- Глобально: `ZodValidationPipe`, фильтр ошибок (единый формат), логирование pino (request id), helmet, CORS (для mobile), `@nestjs/throttler`, версия `/api/v1`, Swagger на `/api/docs`.
- `infra/prisma` (Prisma 7 + `@prisma/adapter-pg`), `health` (проверка БД). Redis подключается в BE-5 вместе с очередями.
- Скрипты: `dev`, `build`, `start`, `lint`, `typecheck`, `test`, `test:e2e`, `db:migrate`, `db:seed`, `db:studio`.
- Каркас e2e-тестов: Vitest + SWC + Supertest на отдельной базе `instagram_test` (`.env.test`), миграции применяются перед прогоном.

**Приёмка:** `pnpm --filter @ig/api dev` поднимает API; `GET /api/v1/health` → 200; Swagger открывается на `/api/docs`; `pnpm --filter @ig/api test:e2e` проходит.

## BE-2. Схема базы данных
**Результат:** полная Prisma-схема по [03-database.md](03-database.md), первая миграция, сиды.
- Все таблицы, enum'ы, индексы; расширение `pg_trgm` и CHECK-ограничения нижнего регистра (через SQL в миграции).
- UUID v7 генерируется в приложении (helper в `common`).
- Сиды: 30 пользователей, около 300 постов с картинками (внешние ссылки picsum.photos, пока нет хранилища), подписки, комментарии, сторис, словарь тем; тестовый аккаунт `demo / Demo1234`.

**Приёмка:** `pnpm db:deploy && pnpm db:seed` на чистой БД отрабатывают без ошибок; в `db:studio` видны данные.

## BE-3. Аутентификация
**Результат:** модуль `auth` (A1–A7 из ТЗ).
- Регистрация и вход (argon2id), JWT access на 15 минут (`sub`, `sid`), opaque refresh на 30 дней в таблице `sessions` (хэш), cookie `ig_rt`.
- Ротация refresh-токена с семьями: повторное использование старого токена отзывает всю семью.
- `JwtAuthGuard` (глобальный) + декоратор `@Public()`, декоратор `@CurrentUser()`.
- Подтверждение email и сброс пароля 6-значным кодом (хэш, срок 15 минут, 5 попыток), письма через Mailpit.
- Проверка занятости username, список и завершение сессий.
- Rate limit: вход 5/мин на IP+login, регистрация 3/мин на IP.

**Приёмка:** e2e — регистрация → вход → refresh → reuse старого refresh даёт 401 и отзыв семьи → logout; письмо видно в Mailpit; сброс пароля работает.

## BE-4. Пользователи и профиль
**Результат:** модуль `users`.
- `GET/PATCH /users/me`, `GET /users/:username`, ссылки профиля, смена username (уникальность, нижний регистр).
- `PolicyService`: `canView(viewer, owner)` — приватность и блокировки. Используется всеми выдачами далее.
- `relationship` в ответе профиля.

**Приёмка:** e2e — гость видит публичный профиль, но не видит постов приватного; заблокированный получает 404.

## BE-5. Медиа-пайплайн
**Результат:** модули `media`, `infra/redis`, `infra/storage`, `infra/queue` (раздел 5.3 архитектуры). Требует Redis и S3 (MinIO): установить Docker Desktop и `docker compose up -d`.
- Presigned PUT в S3 (MinIO), лимиты по типу и `purpose`, проверка mime и размера.
- Воркер BullMQ `media`: sharp (WebP 1080/640/320, blurhash, удаление EXIF, авто-поворот), ffmpeg (MP4 H.264 720p, постер, длительность). Повторы с backoff, статус `FAILED`.
- Событие `media.ready` → сокет (после BE-14) или поллинг `GET /media/:id`.
- Аватар: `PUT /users/me/avatar`.
- Задача `cleanup`: удаление непривязанных медиа старше 24 часов.

**Приёмка:** загрузка JPEG и MP4 → статус `READY`, варианты лежат в хранилище; файл больше лимита отклонён.

> **Сделано без Docker (2026-10-29):** хранилище `StorageDriver` с локальным драйвером (диск, раздача `/media-files`), очередь `JobQueue` с обработкой внутри процесса и повторами. Драйвер S3 (MinIO/R2) и очередь BullMQ (Redis) подключаются за теми же интерфейсами, когда появится Docker — отдельная задача **BE-5b**.

## BE-6. Подписки, блокировки, отношения
**Результат:** модули `follows`, `blocks`.
- Подписка и отписка с учётом приватности (`PENDING`), заявки (принять, отклонить), удаление подписчика.
- Блокировка (каскадно удаляет подписки), Restrict, Mute, Favorites, Close Friends.
- Списки подписчиков и подписок с поиском, рекомендации подписок (друзья друзей + популярные).
- Счётчики в транзакции; события `user.followed`, `follow.requested`, `follow.accepted`.

**Приёмка:** e2e — подписка на приватный аккаунт → `PENDING` → accept → посты видны; блокировка скрывает профиль в обе стороны.

## BE-7. Посты
**Результат:** модуль `posts`.
- Создание поста из готовых медиа (1–20), подпись, парсинг #хэштегов и @упоминаний (общая функция в `@ig/shared`), отметки на фото, геометка, alt-тексты, настройки.
- Редактирование, удаление (мягкое), архив, закрепление (до 3).
- Сетки профиля: посты, Reels, отметки (с учётом `PolicyService`).
- Связь хэштегов и тем (`post_topics`).
- События `post.created`, `user.mentioned`, `user.tagged`.

**Приёмка:** e2e — создание карусели из 3 медиа, хэштеги и упоминания сохранены, пост виден в сетке; чужой пост нельзя изменить (403).

## BE-8. Лайки, сохранения, репосты, коллекции
**Результат:** модули `likes`, `saves`, `reposts`.
- PUT/DELETE идемпотентны (повторный лайк не меняет счётчик).
- Коллекции сохранённого; вкладка «Репосты» профиля; список лайкнувших.
- События `post.liked`, `post.reposted`.

**Приёмка:** e2e — двойной PUT лайка даёт `likesCount = 1`; репост появляется во вкладке профиля.

## BE-9. Комментарии
**Результат:** модуль `comments`.
- Корневые комментарии и ответы (1 уровень), лайки, удаление (автор комментария или поста), закреп (автор поста).
- Учёт `commentsDisabled`, настроек «кто может комментировать», Restrict, скрытых слов.
- События `comment.created`, `comment.replied`, `comment.liked`.

**Приёмка:** e2e — ответ увеличивает `repliesCount`; комментарий с запрещённым словом скрыт для всех, кроме автора.

## BE-10. Лента и «Ваш алгоритм»
**Результат:** модули `feed`, `topics`.
- `GET /feed?mode=home|following|favorites`: курсор, исключение заблокированных, заглушённых и «не интересно».
- Home: подписки за последние N дней + вставка рекомендованных постов каждые 5 позиций, ранжирование по формуле из архитектуры.
- Кэш первой страницы в Redis (60 с), инвалидация при новом посте подписки.
- Веса тем пользователя: автоматический рост от лайков, сохранений и просмотров; ручная правка `/topics/me`.

**Приёмка:** e2e — лента содержит посты подписок в правильном порядке, без постов заблокированных; курсорная пагинация без дублей.

## BE-11. Explore, поиск, хэштеги, места
**Результат:** модули `explore`, `search`, `hashtags`, `locations`.
- Explore: посты с высоким `score` (фоновой пересчёт каждые 10 минут) с учётом тем пользователя; layout-плитки (каждая 5-я — LARGE для Reels).
- Поиск: `pg_trgm` по username, имени, хэштегам и местам; приоритет подпискам; история поиска.
- Страница хэштега (top и recent), страница места.

**Приёмка:** поиск `ale` находит `alex_dev`; хэштег показывает число публикаций; Explore не содержит постов приватных аккаунтов.

## BE-12. Stories и Highlights
**Результат:** модули `stories`, `highlights`.
- Создание (медиа, аудитория, стикеры), tray с порядком «непросмотренные первыми», просмотры, зрители, реакции и ответы (создают сообщения в Direct после BE-15; до этого — заглушка-событие).
- Истечение через 24 часа (фильтр по `expiresAt` + cron в архив), архив, Highlights.
- Close Friends, «скрыть от».

**Приёмка:** e2e — сторис для близких друзей не видна остальным; после `expiresAt` не попадает в tray, но есть в архиве.

## BE-13. Reels и аудио
**Результат:** модули `reels`, `audio`.
- Reels = посты `type=REEL` (видео 9:16, до 3 минут), счётчик просмотров (батч), лента «Для вас» (score + темы) и «Друзья» (лайки и репосты подписок).
- Аудио: оригинальный звук, страница аудио.

**Приёмка:** лента Reels «Друзья» содержит ролик, который лайкнул пользователь из подписок.

## BE-14. Realtime и уведомления
**Результат:** `infra/realtime` (Socket.IO + Redis adapter), модуль `notifications`.
- Авторизация сокета по JWT, комнаты `user:{id}`, presence (онлайн, lastSeen) в Redis.
- Обработчики событий из BE-6…BE-13 → запись уведомления (с `groupKey`) → `notification:new` в сокет.
- Группировка и разделы по времени, счётчик непрочитанных, настройки по типам.
- Web push (VAPID, `web-push`) через очередь `notifications`.

**Приёмка:** два клиента: лайк от A → B мгновенно получает `notification:new`; 5 лайков одного поста группируются в одно уведомление.

## BE-15. Direct
**Результат:** модуль `direct`, `notes`.
- Диалоги 1:1 (уникальный `directKey`) и группы, папка «Запросы» для неподписанных, принятие запроса.
- Сообщения всех типов из [03-database.md](03-database.md), `clientId` для идемпотентности, ответы, реакции, редактирование (15 минут), отмена отправки.
- Сокеты: `message:new`, `typing`, `conversation:read`; счётчик непрочитанных.
- Шеринг поста и профиля, ответы и реакции на сторис (подключить в BE-12).
- Notes (24 часа). Отложенная отправка — delayed job BullMQ (P2).

**Приёмка:** e2e — сообщение с тем же `clientId` не дублируется; заблокированный не может написать; сокет доставляет сообщение второму участнику.

## BE-16. Настройки, приватность, модерация
**Результат:** модули `settings`, `reports`, `admin`.
- Настройки приватности (комментарии, упоминания, сообщения, скрытые слова), настройки уведомлений.
- Жалобы, минимальная админка (`RolesGuard`), бан пользователя (отзыв сессий).
- Деактивация и удаление аккаунта (анонимизация).

**Приёмка:** e2e — `allowMessages: FOLLOWING` блокирует сообщения от неподписанных; админ банит пользователя → его сессии отозваны.

## BE-17. Надёжность и производительность
- Reconcile-job счётчиков, индексы по результатам `EXPLAIN ANALYZE` для ленты, Explore и поиска.
- Кэширование профилей и tray сторис в Redis, нагрузочный тест k6 для ленты (p95 < 200 мс на сидовых данных).
- Sentry, метрики (prom-client), graceful shutdown воркеров.

## BE-18. Карта (P2)
- PostGIS, `GET /map/posts?bbox=`, кластеризация точек на сервере.
